# Veloop 0.3.1 Release Design

## Goal

Publish Veloop 0.3.1 directly from `main` without a pull request. This patch
release contains the cross-application caret positioning correction and its
regression coverage, with no unrelated product changes.

## Versioning

- Set the public version to `0.3.1` everywhere it is tracked or displayed.
- Increment the private bundle build identifier from `9` to `10` in both app
  bundles and their tests.
- Use tag `v0.3.1` and GitHub Release title `Veloop 0.3.1`.
- Keep internal build identifiers out of public release notes.

## Release Preparation

Update `AppConstants`, both bundle property lists, release metadata tests,
English and Chinese README download references, and the Homebrew cask. Update
the local packaging scripts so they create and verify
`Veloop-0.3.1-universal.dmg` with the new bundle metadata.

The DMG is built before the final cask checksum is committed because the cask
stores the DMG digest but is not packaged into the application. The verified
DMG is retained unchanged after its digest is written to the cask.

Generate `update.json` with one concise English item and one concise Simplified
Chinese item describing the corrected clipboard overlay placement at the
current text caret across supported editors.

## Verification

Before pushing `main`:

- run the full Swift test suite;
- build the universal DMG;
- verify the DMG structure, bundle metadata, signatures, and arm64/x86_64
  architectures;
- verify `update.json` version, release URL, bilingual notes, and size bounds;
- record byte sizes and SHA-256 digests for both release assets;
- confirm `main` is clean and based on the latest `origin/main`.

The already completed local integration evidence covers Notion and TextEdit.
The release notes will state that macOS may require Accessibility to be enabled
again after installing a changed ad-hoc signed build.

## Publication

Push `main` directly to `origin`. Create annotated tag `v0.3.1` at the verified
release commit and push it. Publish a normal, non-draft GitHub Release with the
DMG and `update.json`, then verify the remote tag, release title, asset names,
sizes, and GitHub-hosted digests. Download the published assets and compare
their SHA-256 digests with the local files.

## Failure Handling

Stop before tagging if any version, test, build, package, signature, or digest
check fails. Never replace an existing tag or release. If the tag push succeeds
but Release creation fails, keep the tag unchanged and retry publication with
the same verified assets.
